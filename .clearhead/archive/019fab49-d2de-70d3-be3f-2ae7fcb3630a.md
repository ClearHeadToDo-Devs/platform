# Archival

A charter going over the work that needs to be done for the archival process

## Design notes (2026-07-28): archival crystallizes — flat UUID facts, structure in the file

The charter's final section. It settles what happens to a charter's artifacts when it closes, and reframes `archive/` from a relocation target into the **fact-store** the ontology (2026-07-26) has been pointing at: `archive/` is where continuants crystallize into durable occurrents. That reframing changes archival's *mechanism*.

**The reframing: archival is a phase transition, not a move.** A live charter is a continuant — path-structured, human-navigated, mutable, addressed by a human name. A closed charter is a *fact* — self-contained, content-structured, immutable, addressed by identity. Archival is the crystallization between them, so the archived form is optimized for the fact-store's consumer (graphd projecting history over live + archived facts; analytics), not for a human who no longer edits it. This is *permission* to make the archive an append-only store of immutable data instead of a live place where humans and tools are expected to be living.

**The read side is currently free.** Nothing reads `archive/` by filename — discovery actively excludes the region, and there is no archive reader anywhere in `store/` (the "reference resolution can look into archive/" the earlier archive charter promised was never built). The archive is *write-only* today. So changing the on-disk naming breaks nothing; we are shaping the substrate ahead of its reader, deliberately.

**Decision — flat, UUID-stemmed, self-contained.**

- Every archived charter's quartet — `<uuid>.md`, `<uuid>.actions`, `<uuid>.completed.actions`, `.<uuid>.json` sidecar — shares the charter's **UUID as stem**, dropped flat into `archive/`. The UUID is the only honest key for an immutable fact: names collide over time and are mutable; keying a fact by a name is a category error. Flat UUID stems are also what finally makes flattening *safe* — two charters' `next.actions` collided in a flat dir before (why the old code kept subdirs); distinct UUIDs disambiguate.
- **Structure lives in content, not path.** Charter hierarchy reconstructs from `parent:` in frontmatter, never from directory nesting. The archive is a forest whose parent pointers may aim into the live space (a child archived while its parent stays active) — correct and expected; it was never going to be a closed tree.
- **Supporting files carry the owner:** `<charter-uuid>.inventory.md` — flat, owned, keeping a no-UUID note tied to its charter.

**Decision — materialize outbound alias edges as UUIDs at archive time (`parent:` only, for now).** This is the shift that *ends* archival's "verbatim move" identity. Flat UUID naming destroys the one place a directory-nested child's parent link lived — its directory position — so the edge has to be re-homed *into the file* or it is lost outright. And even where a `parent:` line already exists, leaving it as an alias lets the structural edge ride a mutable, collision-prone name (the same category error one level down). So at archival we take the loader-resolved parent — `mc.parent`, populated from an explicit `parent:` key *or* inferred from directory position (`load.rs`) — resolve it to the target charter's UUID against the live workspace (charters *are* loaded, with `.id` and `.alias`), and **ensure a `parent:` line carrying that UUID exists in the archived `.md`: its value substituted when a line was present, the line inserted when it was not.** The insert case is the *common* one here, not an edge: most sub-charters are directory-form and carry no `parent:` line at all — their parenthood lived only in the tree we are about to flatten. Deriving hierarchy from *data* rather than from *mirrored structure* is exactly what lets us flatten safely: a mirrored directory tree would reintroduce the old-charters-with-colliding-aliases problem the flat UUID scheme exists to avoid. This is the invoice-snapshots-the-price-at-sale principle applied to a charter's edges — the archived node records who it pointed at *at crystallization*, immune to later alias churn.

`objectives:` is the same *shape* (a charter points at objective files by alias) and belongs to the same class — but it is **deferred, not done here.** The substrate can't honor it yet: `DomainModel` is built with `objectives: vec![]` (`store/load.rs`), so objectives are never loaded and there is no alias→UUID map to resolve against. Normalizing `objectives:` would first require building objective-loading — a separate, larger concern well outside this scope. "Handle the class, not the case" holds as *intent*; today the class has exactly one resolvable member. Leave `objectives:` untouched until objectives are real, then extend the same pass.

**Surgical, not re-serialized.** The only structural change is the `parent:` line itself — its value substituted, or the line inserted into the frontmatter block when absent — leaving every other byte of the `.md` (other frontmatter keys and their order, keys the model doesn't know about, body prose, headings) exactly as written. It is *not* a round-trip through `format_charter` (charter.rs), which canonicalizes key order and silently drops any frontmatter key outside the set it models. "Only the parent edge changes" has to be *literally* true, so this is a targeted frontmatter edit, not a parse-and-reprint.

**What does NOT change: still plaintext.** Normalization rewrites *field values inside* the `.actions`/`.md` plaintext; it is not a format change. The 2026-07-17 "no Turtle, no JSON-LD on archive; RDF regenerates on read" decision holds untouched. The word that moves is *verbatim*, not *plaintext* — `archive_charter.rs` goes from a byte-faithful relocator to a crystallization pass (read → normalize → write).

**Decision — the sidecar rides the same UUID, and self-identifies.** The quartet is stemmed on the charter's UUID, so the archived sidecar's name derives *automatically*: `sidecar_path("<uuid>.actions") → .<uuid>.json`, agreeing with the actions file by construction — no path-mirroring, and the flat-dir collision the old code feared (two `.next.json` sidecars) can't arise. Beyond the name, archival *guarantees* the sidecar's own `charter.id` field (`CharterMeta.id`) is populated from the known charter UUID — stamped if absent — so a lone `.<uuid>.json` in the flat archive declares its charter in its *content*, not merely its filename. That is the archive ethos (structure in the file) applied to the sidecar. Archival does not depend on `doctor` having run: `doctor` is the standing repair loop that keeps the *live* world's `charter.id ↔ frontmatter id` agreement honest; archival stamps its *own* output on the way out. They reinforce; neither substitutes.

**Side effects are warranted when the alternative is improper archiving.** Archival is no longer a pure relocation — the crystallization pass reads, resolves, stamps, and rewrites. Where a side effect (stamping a missing `charter.id`, resolving an alias edge to UUID) is what makes the archived fact correct and self-contained, it is the right call: a name-dependent, half-attached fact is the worse outcome. This licenses *self-containing* side effects specifically; it is still bounded by the scope guard below, not a blank cheque to reshape data.

**Scope guard.** "Better for analytics" is bought by **self-containment** — rename + ref-normalization — full stop. It is *not* license to denormalize fields, flatten hierarchy into rows, or add analytics-shaped structure to archived files. The analytics consumer does its own shaping over clean, self-contained nodes; the archived file stays a faithful `.actions`/`.md`. Hold that line or this becomes a far larger project.

**Explicitly out of scope.**

- **Action-level alias refs.** A `.actions` line's `<predecessor` is the same category error one level down, but normalization here is scoped to *charter frontmatter edges* (`parent:`). Action-ref normalization is deliberately not attempted — call it out so "normalize outbound alias refs" isn't read broader than what ships.
- **`objectives:` normalization** — deferred until objectives are loaded (see the normalization decision above).
- **Migrating the existing archive.** The name-addressed archive already on disk is inert (nothing reads it), so it is *not* migrated as part of this — a cosmetic one-time rename script is trivial, separable, and deferred.
